# AGENTS.md

Guidance for AI coding agents (and humans) working in this repository.

## What this repo is

The website of the Palo Alto Amateur Radio Association (PAARA), served at
<https://paara.org>. It is a Jekyll site on the `pages-themes/architect` remote theme,
with a local layout override in `_layouts/`. Most changes are content edits to Markdown
pages made by volunteer club members. Helper scripts live in `script/`.

`master` is production: every merge to it publishes the site. `README.md` is the
how-to for site maintenance and `PREVIEW.md` for running the site locally.

## Site requirements

Every change to content, layout, CSS or JS must meet these:

- **Mobile-friendly (MUST).** No horizontal scrolling at phone width. Images, tables
  and embeds scale down. Tap targets are big enough for a finger.
- **Accessible (MUST).** Follow WCAG 2.1 AA: meaningful `alt` text on every image
  (`alt=""` only for decorative ones), headings in order, descriptive link text,
  sufficient color contrast, information never conveyed by color alone, keyboard
  access with visible focus, and a `title` on every iframe.
- **Light and dark mode (MUST).** Light is the default; dark applies under
  `html[data-theme="dark"]` (`assets/css/dark.css`). New UI and colors must look right
  and stay readable in both.
- **American English (SHOULD).** Keep the existing formats in structured fields such
  as meeting dates.

## Ground rules

- **Never push to `master` directly.** Work on a branch and open a PR.
- **Open every PR as a draft.** A human marks it ready for review. Never mark a PR
  ready yourself.
- **Keep changes small and on-topic.** One logical change per PR. Don't reformat or
  reword unrelated content. Long-lived club records (bylaws, constitution,
  incorporation) change only when asked.
- **Never invent facts.** Dates, times, call signs, names, contact details, links,
  frequencies and prices come from the user or existing content. If something is
  missing, leave the placeholder or ask.
- **Personal data:** publish only member details the user supplied for that purpose or
  that are already on the site.
- **No secrets in the repo.** Tokens and API keys are passed via the environment or
  flags.
- **No large binaries.** Presentations go in
  [`PAARA-org/paara.org-attachments`](https://github.com/PAARA-org/paara.org-attachments),
  newsletters in [`PAARA-org/PAARAgraphs`](https://github.com/PAARA-org/PAARAgraphs),
  photo albums in Google Drive. Images committed here should be web-sized.
- **No new dependencies or toolchains** (gems, npm packages, Go modules, Python
  packages) without asking.
- **Never add agent attribution**, anywhere: no `Co-Authored-By` trailers naming an AI
  agent or tool, and no "Generated with ..." lines or badges in commits, PR or issue
  text, comments or code, even if your tool adds them by default.

## Generated and coupled files

Some files are generated or must stay in sync. Use the scripts; don't hand-edit
generated output. `README.md` has the exact commands.

- `meetings.md` and `fieldday.md` are symlinks to the current meeting and Field Day
  pages.
- The past-meetings index (`_includes/meetings-template.md`) is generated from the
  meeting pages. Regenerate it after changing any meeting page.
- The homepage meeting box and raffle (`_includes/meeting-short.md`,
  `_includes/raffle.md`) must match the current meeting page and its raffle include.
- Photo gallery data (`_data/galleries.json`, `assets/data/photos-manifest.json`) and
  `newsletter.md` are generated by scripts.
- `assets/vendor/` is copied from `node_modules` on `npm install` and is gitignored.
- The monthly rollover script is not idempotent. Confirm with the user that a rollover
  is due before running it, and never run it twice.

## Conventions

- Match the surrounding file: heading style, link style, date formats, and whether
  links use root-absolute paths or `relative_url`.
- External links open in a new tab (`{:target="_blank"}`); internal links don't.
- Call signs are uppercase. Write "PAARA" and "PAARAgraphs" exactly like that.
- Keep the friendly, volunteer-club tone. No marketing copy.
- Shell scripts must run on both Linux and macOS. Python uses the standard library
  only. Go is `gofmt`ed, with offline tests. Front-end code is plain JS and CSS with no
  build step; third-party front-end code is vendored, not loaded from a CDN.

## Verifying changes

```sh
./preview.sh                     # http://localhost:4000; add --host 0.0.0.0 for phones and tablets
script/cibuild                   # what CI runs: build, internal links, HTML, orphans, lint, W3C
npm install && script/check-pages   # after a build: accessibility and phone-width layout
```

CI runs on every push and PR. External links are checked weekly by a separate
workflow that files an issue, so a dead outside site doesn't block merging.

Look at changed pages in the preview at phone width and in both light and dark mode.

## Commits and PRs

- Short, imperative subjects that say what changed on the site, e.g.
  `Add raffle info for the 11/2026 meeting`.
- Keep commit messages and PR descriptions brief.
- Don't commit build output or dependencies (`_site/`, `vendor/`, `node_modules/`,
  `assets/vendor/`, `.jekyll-cache/`).
